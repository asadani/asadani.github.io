# Site Uplift — Shared CSS + Build Script, Landing Rework, Publications Buckets

**Date:** 2026-06-21
**Status:** Approved design, ready for implementation plan
**Scope:** asadani.github.io homepage + authoring pipeline

## Problem

The site is hand-rolled static HTML on GitHub Pages. Every article ships with a
full inline `<style>` block, and the 25 existing articles have drifted (inline CSS
ranges 302–872 lines; only 2 of 25 share the current `--accent` value). The homepage
`index.html` (~1600 lines) carries a hand-maintained list of `.art-row` blocks plus
an inline-CSS design system. At a target cadence of ~1 post/week this creates two
compounding costs:

1. A global restyle requires editing every article file (no shared stylesheet).
2. Every post is a manual two-step: generate the page *and* hand-edit a 1600-line
   homepage to add a row.

This spec covers three workstreams that remove that friction and reframe the homepage
as a publication, without leaving GitHub Pages.

## Decisions (locked)

- **Hosting:** stay on GitHub Pages. Not in scope to change.
- **Build mechanism:** a local, zero-dependency `build.js` (Node 18, already present)
  that produces static HTML output committed to the repo. No Jekyll, no SSG, no CI.
- **Legacy articles:** the 25 existing article *pages* are frozen byte-for-byte
  (inline CSS, print rules, interactive scripts untouched). Their homepage *list
  entries* are migrated once into a data file so the generated list still shows them.
- **Landing:** Direction A — hero with a one-line positioning statement + three pillar
  cards (Writing / Papers / Books & Digital) with live counts, funneling into the work.
- **Publications:** one `#research` section split into three labeled buckets —
  Books · Papers · Digital — all rendered from data.

## Architecture

### New files

```
/assets/site.css                ← the design system, extracted once: CSS variables
                                   (:root light + [data-theme="dark"]) and ALL shared
                                   components. Linked by the homepage and every NEW
                                   article. Single source of truth for global restyles.
/data/articles.json             ← array of article entries. Source of truth for the
                                   Articles list AND the "Writing" pillar count.
/data/publications.json         ← { books:[], papers:[], digital:[] }. Source of truth
                                   for the Publications section AND the "Papers" and
                                   "Books & Digital" pillar counts.
/templates/index.template.html  ← homepage skeleton (nav, hero, About, footer authored
                                   by hand) with injection markers for generated blocks.
/build.js                       ← plain Node, no npm install. Reads data + template,
                                   renders cards/rows, computes counts, writes index.html.
```

### Changed files

```
/index.html             ← becomes BUILD OUTPUT (generated by build.js, committed).
/_template/article.html ← inline <style> block replaced with
                          <link rel="stylesheet" href="/assets/site.css">.
                          Pre-paint theme <head> script stays inline. Placeholders
                          unchanged, so github-page-write keeps working.
```

### Data flow

```
data/articles.json  ─┐
data/publications.json├─► build.js ──► index.html (static, committed)
templates/index.template.html ─┘            │
                                            └─ client JS (search/filter/pagination,
                                               theme toggle) runs on generated DOM,
                                               unchanged from today.
```

Per-post authoring loop after this lands:

1. Skill writes `topic-slug/index.html` (lean page linking `/assets/site.css`).
2. Skill appends one entry to `data/articles.json`.
3. `node build.js` regenerates `index.html`.
4. `git commit && git push`.

## Components

### 1. `/assets/site.css` (shared design system)

- Contents: the full design system per `CLAUDE.md` — CSS variables for light (`:root`)
  and dark (`[data-theme="dark"]`), plus every shared component class (nav, hero, banner,
  toc, section, plain-english, cards-grid, callout, code-block, dl, data-table, footer,
  and the homepage-specific pieces: `.pub-card`, `.book-card`, `.store-card`,
  `.interest-card`, `.pagination`, filter/flavor bars).
- Extracted from the *current* homepage + template CSS (the canonical, newest design).
- One stylesheet for the whole live site (homepage + new articles). Slight over-inclusion
  per page is offset by it being cached once across the site vs. duplicated inline.
- The pre-paint theme-selection script remains inline in each page `<head>` (it must run
  before first paint; cannot move to an external stylesheet).

### 2. `/data/articles.json`

One object per article. Fields derived from the existing `.art-row` markup:

```json
{
  "slug": "the-monk-who-oversold-the-ai",
  "title": "The Monk Who Oversold the AI",
  "date": "2026-06-18",
  "topic": "ai-engineering",
  "flavors": ["models", "research"],
  "quote": "You can rent capability. You cannot rent a moat.",
  "desc": "A product leader replaced the company's R&D with borrowed...",
  "shareUrl": "https://asadani.github.io/the-monk-who-oversold-the-ai/"
}
```

- `topic` drives the Topic pill + badge class; `flavors` drives the Flavor chips.
- `build.js` sorts entries by `date` descending before rendering, so file order does
  not matter and new entries can be appended anywhere.
- One-time migration: extract all 25 current rows into this file mechanically. The 25
  article HTML files are NOT modified.

### 4. `.store-card` (new Ko-fi card variant)

- Structure mirrors `.book-card`: accent left strip + thumbnail image + body
  (title, one-line desc) + footer with a "View on Ko-fi ↗" CTA.
- Accent uses `--accent` (terracotta) to distinguish from `.pub-card` (blue strip) and
  align with the store/"buy" affordance already used by `.book-cta`.
- Colors come entirely from existing CSS variables so light/dark just works.
- Thumbnails reference the large in-dir PNGs; image optimization is an OPTIONAL
  follow-up, not a blocker for this work.

### 5. `templates/index.template.html`

- Hand-authored skeleton: nav, hero, About block, footer, and the inline pre-paint
  theme script. Links `/assets/site.css`.
- Injection markers consumed by `build.js`:
  - `<!-- BUILD:pillars -->` — hero pillar cards with computed counts.
  - `<!-- BUILD:publications -->` — the three Publications buckets.
  - `<!-- BUILD:articles -->` — the `.art-row` list.
- Section order: **hero → Articles (#articles) → Publications (#research) →
  About (#about: Journey, Skills, Interests consolidated)**.

### 6. `build.js`

- Plain Node 18, zero npm dependencies (uses `fs` + string/template replacement only).
- Steps: read the two JSON data files + the template; compute pillar counts
  (Writing = `articles.length`, Papers = `papers.length`, Books & Digital =
  `books.length + digital.length`); render the three injected blocks; write `index.html`.
- Deterministic and idempotent: running it twice with unchanged inputs produces an
  identical `index.html`.
- HTML-escapes data-derived text to avoid breaking markup.

### 7. Hero pillar cards (Direction A)

- Three cards after the hero deck: **Writing** (→ `#articles`), **Papers** (→ `#research`),
  **Books & Digital** (→ `#research`). Each shows its live count.
- Counts injected by `build.js`; never hand-edited.

### 8. About block

- Journey (career), Skills, and Interests — the existing sections — consolidated under a
  single `#about` section anchor, repositioned to the bottom of the page. Content
  preserved; only grouping/position changes.

## Sequencing

All workstreams ship together in one pass, built in this order:

1. **Item 2 foundation** — extract `/assets/site.css`; create `build.js`,
   `templates/index.template.html`, and `data/articles.json` (migrate 25 rows);
   verify the generated `index.html` matches the current homepage's article list and
   behavior (search/filter/pagination/theme toggle).
2. **Item 4** — add `data/publications.json`, the `.store-card` CSS, and the three-bucket
   Publications rendering; fold in SSRN; wire Ko-fi cards with thumbnails.
3. **Item 3** — rework the hero into Direction A with pillar cards + counts; consolidate
   Journey/Skills/Interests into the About block; finalize section order.
4. Update `_template/article.html` to link `/assets/site.css`.

## Out of scope (explicit YAGNI)

- Migrating the 25 legacy article pages to the shared stylesheet.
- Adopting Jekyll, an SSG, or CI/GitHub Actions.
- A custom domain (recommended separately; not part of this work).
- Image optimization of the Ko-fi PNGs (optional follow-up).
- A dedicated `/publications/` page (only needed if the section outgrows the homepage;
  not yet).

## Success criteria

- `node build.js` regenerates `index.html` deterministically from data + template.
- The generated homepage is visually and behaviorally equivalent to today's for the
  Articles list (same rows, search, filter, pagination, theme toggle), plus the new
  hero pillars, three Publications buckets, and About block.
- Adding a new post is: write the article page, append one JSON entry, run `build.js`,
  commit — no hand-editing of `index.html`.
- A global restyle is a single edit to `/assets/site.css` that reaches the homepage and
  all new articles.
- The 25 legacy article files are unchanged (verified via `git diff` showing no edits to
  their `index.html`).
