Decision Firewall: what building an AI governance framework taught me.

This is a synthetic narration generated locally with Kokoro. Tables are adapted into spoken comparisons; code listings and source links are available in the written article.

A refund can succeed while the application thinks it failed. The payment service moves the money, its response disappears, and the next retry becomes the dangerous part.

That was the kind of problem I wanted Decision Firewall to handle. I started with a model interpreting a customer request and a separate control layer deciding whether an exact action could execute. Then I expanded it into a framework.

The controls worked in the tested cases. The case for the framework was weaker. A separate paired agent pilot found equal correctness against competent application controls, more integration friction and a slower implementation. I kept the code and narrowed its purpose.

I’ve open-sourced Decision Firewall, including the reference implementation, conformance checks and evaluation reports. Its new code is Apache two point zero licensed. The simulated workflows run without a model.

This is the build story I wish I had read before expanding the scope. I directed the implementation through coding agents; my work was choosing the boundaries and challenging the evidence. The comparison measured agent builds, not human productivity.
